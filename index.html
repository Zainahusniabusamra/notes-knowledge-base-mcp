The gap

Knowing your notes exist isn't the same as reading them.

An AI assistant can talk about note-taking in general. MCP is what lets it actually open your data/ folder and answer from what's really written there.

Without MCP

> user: search my notes for photosynthesis

< "I don't have access to your notes."

Nothing searched. Nothing returned.

With this MCP server

> user: search my notes for photosynthesis

> search_notes(query: "photosynthesis")

3 matching notes returned from data/

Architecture

One request, one machine, no branching out.

Every tool call stays local — there's no external API to authenticate against, no cloud database to sync with.

MCP toolbox

Three tools, one job each.

Registered from src/index.ts and validated with Zod schemas.

FOUND
⌕ search_notes

Search notes stored in data/ by keyword and return the matching notes. Limit defaults to 5, capped at 20.

in: query, limit?
out: matching notes[]
FILED
≡ get_note

Retrieve a single note by its identifier, e.g. biology.md. Returns a safe error if it doesn't exist — never a filesystem path.

in: note_id
out: note content
SAVED
＋ create_note

Create a new Markdown note from a title, content, and optional tags. Title ≤200 chars, content ≤10,000 chars, ≤10 tags.

in: title, content, tags?
out: saved note
See it in action

From request to a note on disk.

Two real flows, tool call by tool call — straight from the example prompts in the README.

workflow — search notes
user "Search my notes for photosynthesis."
> search_notes(query: "photosynthesis")
✓ 3 notes matched, returned from data/
workflow — create a note
user "Create a note titled 'Exam Reminder' with the content 'Review mitosis before the exam'."
> create_note(title, content)
✓ Saved to data/exam-reminder.md
Project highlights

What actually shipped.

Verified against the repository README — no invented metrics.

  • Three MCP tools covering the full note lifecycle: search, retrieve, create
  • Local Markdown storage in data/ — no database, no internet connection required
  • Every tool input validated with Zod, including strict length and tag-count limits
  • Runs over the standard MCP stdio transport for any compatible client
  • Testable interactively with the MCP Inspector
  • Missing or invalid note_id returns a safe error, not a filesystem leak
  • Built with the official @modelcontextprotocol/sdk and TypeScript
  • MIT licensed and public on GitHub
